# agentic-finance-ops-demo

Multi-agent system for finance & operations workflows: reconciliation, variance analysis, AR/AP, close automation. Built with FastAPI, LangGraph, and audit-ready controls.

## Why this project matters
This portfolio project demonstrates how a Forward Deployed Engineer can deliver an auditable AI workflow for finance operations. It is designed to look like a real client-ready solution for variance analysis, reconciliations, and month-end close support rather than a toy prototype.

## What is included
- Multi-agent LangGraph workflow for finance variance review
- Sample GL, forecast, and close-related operational data
- Audit logging with citations and control checks
- Human-in-the-loop approval checkpoint
- FastAPI endpoints for workflow execution and audit trail retrieval
- Docker Compose setup for local execution
- Clerk-ready configuration notes for enterprise auth integration

## Example use cases
1. Variance analysis for a quarterly close: compare actuals against forecast and explain material movement.
2. AR/AP review: identify aged receivables and operating expense drift in a month-end review.
3. Revenue and margin check: spot deviations across sales, cost, and overhead categories before a signoff.

## Architecture overview

```text
+---------------------+      +----------------------+      +-------------------+
| Finance Data Source | ---> | Data Extraction      | ---> | Normalization      |
| (mock ERP/CRM)     |      | + source citations   |      | + control marks    |
+---------------------+      +----------------------+      +-------------------+
                                                       |
                                                       v
                                         +----------------------------+
                                         | Reconciliation Agent       |
                                         | GL vs forecast alignment   |
                                         +----------------------------+
                                                       |
                                                       v
                                         +----------------------------+
                                         | Variance Agent              |
                                         | Variance explanations       |
                                         +----------------------------+
                                                       |
                                                       v
                                         +----------------------------+
                                         | Human Approval Checkpoint   |
                                         | SOX / close review gate     |
                                         +----------------------------+
                                                       |
                                                       v
                                         +----------------------------+
                                         | Audit Summary Agent         |
                                         | citations + controls + log  |
                                         +----------------------------+
                                                       |
                                                       v
                                           FastAPI API / Streamlit UI / audit trail
```

## Workflow steps
1. Extract: pull source data and metadata from ERP/CRM-like systems.
2. Normalize: standardize account names, periods, and units.
3. Reconcile: compare actuals to forecast and identify mismatched accounts.
4. Variance check: calculate variance and explain material drivers.
5. Human approval: represent a control checkpoint before final release.
6. Summary: compile final audit-ready output with citations and control status.

## Local development

### Requirements
- Python 3.11+
- Docker + Docker Compose

### Start locally
```bash
docker-compose up --build
```

Then open:
- API: http://localhost:8000/docs
- Root service: http://localhost:8000/

## API example

### Request
```bash
curl -X POST "http://localhost:8000/finance/analyze-variance" \
  -H "Content-Type: application/json" \
  -d '{
    "user": "analyst_001",
    "approval": true,
    "gl_summary": [
      {"account": "Revenue", "amount": 8725000, "source_system": "Oracle ERP GL", "extraction_time": "2026-09-30T18:30:00Z"},
      {"account": "Payroll", "amount": 3450000, "source_system": "Oracle ERP GL", "extraction_time": "2026-09-30T18:30:00Z"}
```

## Deployment notes
This project is structured to be deployable in a containerized environment and can be extended to Kubernetes with a standard deployment manifest, health checks, and ingress configuration.

See the deployment guide in `docs/deployment.md` for a representative Kubernetes-ready plan.

## Clerk configuration
This repository is designed to be compatible with a Clerk-backed authentication pattern for enterprise-facing demos. Set the following values in your environment or secrets manager:

```bash
export CLERK_PUBLISHABLE_KEY=pk_test_...
export CLERK_SECRET_KEY=sk_test_...
```

In a real client deployment, the audit workflow would enforce role-based access for analyst, reviewer, and approver roles before final variance signoff.

## Controls and auditability
- Every workflow step emits an audit event.
- Each operational result carries citations to source systems and extraction metadata.
- Human approval is represented as a required checkpoint before final report generation.
- Control marks are included for SOX-style review discipline and reproducibility.
